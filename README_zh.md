# 寻找 Great Work

[English](README.md) | 中文

我们领域的论文数量正在爆发式增长。其中大多数一年之后就不会再有人读，多加一篇也改变不了什么。

曹老师的团队要找的是 great work，而不是更多的论文。我们以 Paul Graham 的这篇文章为标准：

**How to Do Great Work** — https://paulgraham.com/greatwork.html

这篇文章讲的不只是科研，它同样适用于做产品和创业。他给出的定义是：great work 是把一件重要的事做得足够好，以至于拓展了人们对"什么是可能的"的认识。希望它能帮你找到重要而有意义的项目，值得你投入时间和职业生涯。

## 1. 首要问题

请把下面的内容放在 proposal 的开头。

### 用一段话介绍你的项目

用大白话说明你想做什么。尽量不用缩写和时髦的术语。要让一个不在你这个子领域的读者也能看懂你的主张是什么、为什么重要。

### 三个问题

每个问题用 1–2 句话回答。可以自己总结，可以指向 proposal 里的某一节，也可以直接引用原文。"我还不知道"是可以接受的回答，它比一句漂亮但空洞的话有用得多。

**1. Scope 与雄心**

如果这件事完全做成了，会有什么不一样？有两条路可以过关：一是有真实的应用，能改变人们做事的方式；二是让研究领域的认知发生真正的变化。在某个 benchmark 上多几个点，两者都不算。请放在全世界来看，把已有的工作和正在做同一问题的其他团队都考虑进去：你的结果是"又一篇论文"，还是别人绕不开的东西？

回答之前先问自己：如果直接让 Claude Code 或 Codex 去做，它一天之内能不能做出来？如果能，那是你的基线，而不是你的项目。

第一版可以很小。这里问的是项目指向哪里，而不是现在已经走了多远。

**2. 好奇心**

关于这个问题，你最想知道的是什么？我们要的是你想弄明白的那件事，而不是论文的贡献列表。如果论文被拒了，你还会继续做吗？这个问题是你自己提出来的，还是来自别人论文的 future work？

**3. 为什么是你**

为什么你有真实的成功机会？不要求有把握，但要有值得下注的理由。你有什么别人没有的东西：数据、工具、来自另一个领域的知识、一个别人没有注意到的观察，还是一个已经跑通的初步结果？这个项目需要哪些资源，你现在手头有什么？

### 三个问题之间的关系

这三个问题是层级关系：后一个问题只有在前一个成立时才有意义，所以任何一层明显不过，项目就停在那一层。一个项目要值得做，三项里至少要有一项确实突出。
